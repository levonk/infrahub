## Background

Buzz is a self-hostable Nostr relay workspace where humans and AI agents share rooms. Every message, reaction, workflow step, review approval, and git event is a signed Nostr event. It needs Postgres (event store + FTS), Redis (pub/sub), and S3-compatible object storage (media). The relay exposes a WebSocket on port 3000, a health endpoint on port 8080, and Prometheus metrics on port 9102.

## Design

- **Host ports**: 3101 (relay), 3102 (health), 3103 (metrics)
- **Container ports**: 3000, 8080, 9102
- **Network**: new `buzz-network` (172.38.0.0/16); relay also joins `traefik-network`
- **Domain**: `buzz.levonk.com` (CNAME → `oci.tale-grouper.ts.net`)
- **Storage**: Docker volumes `localnet-buzz-postgres-data-volume` and `localnet-buzz-minio-data-volume`
- **Vault secrets**: `vault_buzz_postgres_password`, `vault_buzz_s3_access_key`, `vault_buzz_s3_secret_key`, `vault_buzz_relay_private_key`
- **Traefik routing**: file-provider dynamic config `buzz-levonk-com.yml` (Docker provider is disabled)

## Known Limitations / Follow-Up

- The WebSocket relay is behind Authelia, which may require Nostr clients to authenticate via SSO first. A future iteration may add a dedicated `buzz-api.levonk.com` route without Authelia for agent/CLI connections.
- The Buzz web UI root (`/`) currently returns 404; the container logs indicate `BUZZ_WEB_DIR=/srv/buzz/web` but no web assets are being served at root. This is an upstream image/packaging question, not an infra issue.
