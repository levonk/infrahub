# PRD: Verdaccio Dual-Deployment NPM Registry

## Summary

Deploy Verdaccio (private npm registry + proxy cache) as two independent instances on the levonk client:
- **cno** (oci-cloud-server, ARM64, Linux): `npmjs.cno.levonk.com`
- **nl** (dtop202311, X86, Windows Docker Desktop): `npmjs.nl.levonk.com`

Both instances proxy npmjs.org, cache packages locally, allow publishing @levonk/* scoped packages, and are fronted by Traefik with Authelia SSO for the web UI.

## Background

Research (see `internal-docs/research/service/verdaccio/`) confirmed Verdaccio as the best choice over Nexus, cnpmcore, pnpr, and Artifactory OSS due to its lightweight footprint, multi-arch Docker support, built-in htpasswd auth, and zero-database design.

Existing scaffolding at `shared/active/03-container/services/artifact/verdaccio/` has a custom Dockerfile + entrypoint. This PRD replaces that approach with the upstream `verdaccio/verdaccio:latest` image + Ansible Jinja2 templates (simpler, no build pipeline, aligns with project conventions).

## Requirements

### Functional
1. Two independent Verdaccio instances (cno + nl), each with separate storage
2. Synced config: same htpasswd, same config template (rendered by Ansible from vault secrets)
3. Proxy npmjs.org with local caching (uplinks)
4. Allow publishing @levonk/* scoped packages (authenticated)
5. Web UI accessible via Traefik + Authelia SSO at `npmjs.{nl,cno}.levonk.com`
6. npm CLI auth via htpasswd/bcrypt tokens (bypasses Authelia — configured in Traefik)
7. Healthcheck endpoint: `/-/ping`

### Non-Functional
1. Upstream image `verdaccio/verdaccio:latest` — no custom build pipeline
2. Ansible Jinja2 templates for config.yaml (not runtime sed substitution)
3. `community.docker.docker_container` on Linux (cno)
4. `ansible.builtin.shell` + `DOCKER_HOST: ssh://` + `delegate_to: localhost` on Windows (nl) — QM pattern
5. All ports/IPs/domains as `infra_*` variables (no hardcoding)
6. Vault handoff for htpasswd secrets (agent provides docker run command, user edits vault)
7. Storage eviction: cron job for proxy cache cleanup (published @levonk/* packages preserved)

### Architecture
- **cno**: Verdaccio container on oci-cloud-server, joins `traefik-network`, Traefik routes `npmjs.cno.levonk.com` → container:4873
- **nl**: Verdaccio container on dtop202311 (Windows), Traefik on OCI routes `npmjs.nl.levonk.com` → `dtop202311.tale-grouper.ts.net:4873` (cross-machine via Tailscale, QM pattern)
- **Authelia**: Web UI behind Authelia SSO; npm CLI endpoints (`/-/npm/*`, `/-/user/*`) bypass Authelia
- **htpasswd**: Generated by Ansible from vault secrets, mounted into container

## Scope

### In Scope
- Shared infrastructure schemas (ports, domains, storage, services.yml)
- Client infrastructure overrides (levonk/)
- DNS records (Cloudflare CNAMEs)
- Ansible role `artifact-verdaccio` (shared)
- Traefik dynamic config templates for both domains
- Vault secrets (htpasswd credentials)
- Deployment playbook
- Validation playbook
- Service catalog entries
- Removal of old custom Dockerfile scaffolding (or marking it deprecated)

### Out of Scope
- Replication between cno and nl instances (independent registries)
- Storage plugins (S3, etc.) — filesystem storage only
- LDAP/SSO auth plugins — htpasswd only
- Multi-format support (Maven, Docker, etc.) — npm only

## Acceptance Criteria

1. `npmjs.cno.levonk.com` resolves and shows Verdaccio web UI (behind Authelia)
2. `npmjs.nl.levonk.com` resolves and shows Verdaccio web UI (behind Authelia)
3. `npm ping --registry https://npmjs.cno.levonk.com` succeeds
4. `npm ping --registry https://npmjs.nl.levonk.com` succeeds
5. `npm publish --registry https://npmjs.cno.levonk.com` works for @levonk/* scoped packages
6. Both containers report healthy via `/-/ping`
7. `ansible-lint` and `ansible-syntax-check` pass
8. No hardcoded IPs or ports in any new file
9. Service catalog regenerated with both entries
