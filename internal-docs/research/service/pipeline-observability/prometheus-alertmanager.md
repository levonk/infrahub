# Prometheus + Alertmanager Deployment Notes

**Project:** infrahub pipeline observability stack (per ADR `adr-202608270001-pipeline-observability-strategy.md`)
**Target hosts:** OCI cloud server, Oracle Linux, mixed ARM64/AMD64 fleet
**Deployment method:** Ansible `community.docker.*` modules only — **never `docker compose`**
**Sources:** see "References & Sources" at the bottom.

> This doc is intentionally implementation-focused: exact image tags, config paths, flags, YAML syntax, and Ansible `community.docker` task patterns. It follows the role-creation pattern in `.agents/workflows/infrahub-add-new-service.md` Phase 5c/5d and the service/port/storage schemas in `shared/active/02-config/ansible/infrastructure/`.

## 1. Prometheus Container Image

| Item | Value |
|---|---|
| Official image | `prom/prometheus` |
| Latest stable tag at research time | `v3.14.0` (release 2026-08-17) — multi-arch `linux/amd64` + `linux/arm64` |
| Production recommendation | Pin to a digest or `v3.14.0`; only use `latest` for dev/test |
| Default config path inside container | `/etc/prometheus/prometheus.yml` |
| Default TSDB data path inside container | `/prometheus` |
| Web UI / API listen flag | `--web.listen-address=0.0.0.0:{{ infra_port_monitoring_prometheus_container }}` |
| Config flag | `--config.file=/etc/prometheus/prometheus.yml` |
| TSDB path flag | `--storage.tsdb.path=/prometheus` |
| Retention flags (CLI) | `--storage.tsdb.retention.time=30d` and `--storage.tsdb.retention.size=10GB` |
| Built-in health endpoints | `/-/healthy`, `/-/ready` |

The official image supports both `amd64` and `arm64/v8` from `prom/prometheus` on Docker Hub, so a single image reference works across the mixed OCI fleet. For Oracle Linux, run the container with `userns-remap` UID 100000 and a named volume for `/prometheus`.

## 2. Prometheus Configuration Format (`prometheus.yml.j2`)

### `scrape_configs` anatomy

```yaml
scrape_configs:
  - job_name: "<name>"
    metrics_path: "/metrics"
    scrape_interval: 15s
    scrape_timeout: 10s
    static_configs:
      - targets:
          - "<host>:<port>"
        labels:
          pipeline: "<pipeline>"
          stage: "<stage>"
          service: "<service>"
    # or
    docker_sd_configs:
      - host: "unix:///var/run/docker.sock"
        refresh_interval: 5s
    relabel_configs:
      - source_labels: [__meta_docker_container_label_prometheus_io_scrape]
        regex: "true"
        action: keep
```

- `static_configs` is the simplest form: a fixed list of host:port targets.
- `docker_sd_configs` connects to the Docker daemon socket and dynamically discovers containers. It is useful for services that may change IPs, but requires mounting `/var/run/docker.sock`.
- `relabel_configs` is where `__meta_*` labels are mapped into real metric labels such as `pipeline`, `stage`, `service`.

### Full example `prometheus.yml.j2`

This is the shared role template. All hostnames and ports are variables.

```yaml
---
# Prometheus scrape configuration for the pipeline-observability stack
# Generated by Ansible — DO NOT EDIT MANUALLY

global:
  scrape_interval: 15s
  evaluation_interval: 15s
  external_labels:
    client: '{{ infra_client | default("levonk") }}'
    cluster: '{{ infra_domain_base }}'

rule_files:
  - '/etc/prometheus/rules/*.yml'

alerting:
  alertmanagers:
    - scheme: http
      static_configs:
        - targets:
            - '{{ infra_hostname_monitoring_alertmanager }}:{{ infra_port_monitoring_alertmanager_container }}'

scrape_configs:
  # Self-monitoring
  - job_name: 'prometheus'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - 'localhost:{{ infra_port_monitoring_prometheus_container }}'
        labels:
          pipeline: 'infra'
          stage: 'monitoring'
          service: 'prometheus'

  # Proxy / ingress
  - job_name: 'traefik'
    scrape_interval: 15s
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ infra_hostname_traefik }}:{{ infra_port_proxy_traefik_metrics }}'
        labels:
          pipeline: 'web'
          stage: 'ingress'
          service: 'traefik'

  # SSO
  - job_name: 'authelia'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ infra_hostname_authelia }}:{{ infra_port_sso_authelia_metrics }}'
        labels:
          pipeline: 'infra'
          stage: 'sso'
          service: 'authelia'

  # Security / IDS
  - job_name: 'crowdsec'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ infra_hostname_crowdsec }}:{{ infra_port_security_crowdsec_prometheus }}'
        labels:
          pipeline: 'infra'
          stage: 'security'
          service: 'crowdsec'

  # DNS resolver
  - job_name: 'coredns'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ dns_coredns_container_name | default("localnet-dns-coredns") }}:{{ infra_port_dns_coredns_main_metrics_host }}'
        labels:
          pipeline: 'dns'
          stage: 'resolver'
          service: 'coredns'

  # DNS router
  - job_name: 'dnsdist'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ dns_dnsdist_container_name | default("localnet-dns-dnsdist") }}:{{ infra_port_dns_dnsdist_metrics_host }}'
        labels:
          pipeline: 'dns'
          stage: 'router'
          service: 'dnsdist'

  # Host metrics
  - job_name: 'node_exporter'
    metrics_path: '/metrics'
    static_configs:
      - targets:
          - '{{ infra_hostname_monitoring_node_exporter }}:{{ infra_port_monitoring_node_exporter_container }}'
        labels:
          pipeline: 'infra'
          stage: 'host'
          service: 'node-exporter'

  # Optional: docker service discovery for any container with `prometheus.io/scrape=true`
  - job_name: 'docker'
    docker_sd_configs:
      - host: 'unix:///var/run/docker.sock'
        refresh_interval: 5s
    relabel_configs:
      - source_labels: [__meta_docker_container_label_prometheus_io_scrape]
        regex: 'true'
        action: keep
      - source_labels: [__meta_docker_container_name]
        regex: '/(.*)'
        target_label: 'container'
```

## 4. Alertmanager Configuration Format (`alertmanager.yml.j2`)

### Sections

- `global` — defaults such as `smtp_smarthost`, `smtp_from`, `slack_api_url`.
- `route` — entry point for all alerts, `group_by`, `group_wait`, `group_interval`, `repeat_interval`, `receiver`, and child `routes` with `matchers`.
- `receivers` — named notification targets (`email_configs`, `slack_configs`, `webhook_configs`, etc.).
- `inhibit_rules` — suppress downstream alerts when the upstream root-cause alert is firing.

### Full `alertmanager.yml.j2`

```yaml
---

The examples above show the Alertmanager-native webhook URL pattern.

## 5. Prometheus Alerting Rules File Format

Rules live under `groups` → `name` → `rules` with `alert`, `expr`, `for`, `labels`, and `annotations`.

```yaml
groups:
  - name: ai_pipeline_node_alerts
    rules:
      - alert: OmnigentDown
        expr: up{job="omnigent"} == 0
        for: 1m
        labels:
          pipeline: 'ai'
          stage: 'agent'
          service: 'omnigent'
          severity: 'critical'
        annotations:
          summary: 'Omnigent container is down'
          description: 'Omnigent (AI pipeline entry point) is not responding to Prometheus scrapes.'

      - alert: LiteLLMDown
        expr: up{job="litellm"} == 0
        for: 1m
        labels:
          pipeline: 'ai'
          stage: 'gateway'
          service: 'litellm'
          severity: 'critical'
        annotations:
          summary: 'LiteLLM gateway is down'
          description: 'LiteLLM gateway is not responding; all AI traffic stops here.'

      - alert: NordVPNEgressDown
        expr: up{job="nordvpn", pipeline="ai"} == 0
        for: 1m
        labels:
          pipeline: 'ai'
          stage: 'egress'
          service: 'nordvpn'
          severity: 'critical'
        annotations:
          summary: 'NordVPN egress is down'
          description: 'AI pipeline cannot reach the internet via the NordVPN exit node.'

      - alert: AIPipelineSyntheticProbeFailed
        expr: probe_success{job="ai-pipeline-omnigent", pipeline="ai"} == 0
        for: 2m
        labels:
          pipeline: 'ai'
          stage: 'synthetic-probe'
          service: 'omnigent-probe'
          severity: 'critical'
        annotations:
          summary: 'AI pipeline end-to-end probe failed'
          description: 'The Omnigent synthetic probe did not return a valid OpenAI-compatible response with token counts.'
```

For "container not even known to Prometheus" (no `up` series), use `absent(up{job="omnigent"} == 1)`. In practice a missing `up` series is treated the same as `up == 0`, so `up{job="omnigent"} == 0` is the normal expression.

## 6. Loading Rules via `rule_files`

Add the glob to `prometheus.yml`:

```yaml
rule_files:
  - '/etc/prometheus/rules/*.yml'
```

The rules directory is mounted into the container from the Ansible template directory:

```yaml
# In the docker_container task
volumes:
  - '{{ monitoring_prometheus_config_dir }}:/etc/prometheus:ro'
```

Ansible renders `prometheus.yml.j2` and all `*.yml` rule files under `monitoring_prometheus_config_dir/rules/`, so the glob matches them.

### `defaults/main.yml` (Prometheus)

```yaml

monitoring_prometheus_container_name: '{{ infra_hostname_monitoring_prometheus }}'

monitoring_prometheus_volume: '{{ infra_storage_monitoring_prometheus_volume }}'
monitoring_prometheus_retention_time: '30d'
monitoring_prometheus_retention_size: '10GB'
monitoring_prometheus_network: '{{ infra_network_monitoring_prometheus_network_name | default("traefik-network") }}'

monitoring_prometheus_healthcheck_interval: "30s"
monitoring_prometheus_healthcheck_timeout: "5s"
monitoring_prometheus_healthcheck_retries: 3
monitoring_prometheus_healthcheck_start_period: "30s"
```

### `tasks/main.yml` — Prometheus

```yaml
---
- name: Validate required Prometheus variables
  ansible.builtin.assert:
    that:
      - monitoring_prometheus_container_name is defined
      - monitoring_prometheus_image_name is defined
      - monitoring_prometheus_image_tag is defined
      - monitoring_prometheus_host_port is defined
    fail_msg: "Missing required Prometheus monitoring variables."

- name: Ensure Prometheus data volume exists
  community.docker.docker_volume:
    name: '{{ monitoring_prometheus_volume }}'
    state: present

- name: Pull Prometheus image
  community.docker.docker_image:
    name: '{{ monitoring_prometheus_image_name }}:{{ monitoring_prometheus_image_tag }}'
    source: pull
    state: present
  notify: restart monitoring-prometheus

- name: Deploy Prometheus container
  community.docker.docker_container:
    name: '{{ monitoring_prometheus_container_name }}'
    image: '{{ monitoring_prometheus_image_name }}:{{ monitoring_prometheus_image_tag }}'
    state: started
    restart_policy: unless-stopped
    networks:
      - name: '{{ monitoring_prometheus_network }}'
    ports:
      - '{{ monitoring_prometheus_host_port }}:{{ monitoring_prometheus_container_port }}/tcp'
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
      - '--web.listen-address=0.0.0.0:{{ monitoring_prometheus_container_port }}'
      - '--storage.tsdb.retention.time={{ monitoring_prometheus_retention_time }}'
      - '--storage.tsdb.retention.size={{ monitoring_prometheus_retention_size }}'
      - '--web.enable-lifecycle'
    volumes:
      - '{{ monitoring_prometheus_config_dir }}/prometheus.yml:/etc/prometheus/prometheus.yml:ro'
      - '{{ monitoring_prometheus_config_dir }}/rules:/etc/prometheus/rules:ro'
      - '{{ monitoring_prometheus_volume }}:/prometheus:rw'
      - '/var/run/docker.sock:/var/run/docker.sock:ro'
    env:
      TZ: '{{ localnet_tz | default("UTC") }}'
    log_driver: json-file
    log_options:
      max-size: "10m"
      max-file: "5"
    healthcheck:
      test: ["CMD-SHELL", "wget --spider -q http://localhost:{{ monitoring_prometheus_container_port }}/-/healthy || exit 1"]
      interval: '{{ monitoring_prometheus_healthcheck_interval }}'
      timeout: '{{ monitoring_prometheus_healthcheck_timeout }}'
      retries: '{{ monitoring_prometheus_healthcheck_retries }}'
      start_period: '{{ monitoring_prometheus_healthcheck_start_period }}'
  notify: restart monitoring-prometheus
```

  notify: restart monitoring-alertmanager
```

**Critical Ansible module notes** (from `shared/active/02-config/ansible/AGENTS.md`):

- `community.docker.docker_container` uses `restart_policy`, not `restart`.
- `healthcheck` interval/timeout/start_period must be strings with unit suffix (`"30s"`), not bare integers.
- `log_options` (not `log_opt`) uses camel-case-ish keys `max-size` / `max-file`.
- Env values must be strings.
- Image pull must use `community.docker.docker_image` with `source: pull`, never `source: build`.

## 8. Promtail Container & Configuration

| Item | Value |
|---|---|
| Official image | `grafana/promtail` |
| Stable multi-arch tag | `3.6.11` (or `latest`) — `linux/amd64` + `linux/arm64` |
| Default config path inside container | `/etc/promtail/config.yml` |
| Default positions file | `/tmp/positions.yaml` or `/etc/promtail/positions.yaml` |
| Command | `-config.file=/etc/promtail/config.yml` |
| Required mounts | `/var/run/docker.sock:ro`, `/var/lib/docker/containers:ro` |
| Loki push endpoint | `http://<loki>:3100/loki/api/v1/push` |

### `promtail.yml` example

```yaml
server:
  http_listen_port: 9080
  grpc_listen_port: 0

positions:
  filename: /etc/promtail/positions.yaml

clients:
  - url: 'http://{{ infra_hostname_monitoring_loki }}:{{ infra_port_monitoring_loki_container }}/loki/api/v1/push'

scrape_configs:
  - job_name: docker
    docker_sd_configs:
      - host: unix:///var/run/docker.sock
        refresh_interval: 5s
    relabel_configs:
      - source_labels: [__meta_docker_container_name]
        regex: '/(.*)'
        target_label: 'container'
      - source_labels: [__meta_docker_container_log_stream]
        target_label: 'logstream'
    pipeline_stages:
      - docker: {}
      - timestamp:
          source: time
          format: RFC3339Nano
      - output:
          source: log
```

### Ansible `community.docker` mount pattern

```yaml
volumes:
  - '{{ monitoring_promtail_config_dir }}/promtail.yml:/etc/promtail/config.yml:ro'
  - '{{ monitoring_promtail_positions_volume }}:/etc/promtail:rw'
  - '/var/run/docker.sock:/var/run/docker.sock:ro'
  - '/var/lib/docker/containers:/var/lib/docker/containers:ro'
```

The `docker: {}` pipeline stage is the recommended way to decode Docker JSON logs. It extracts `log`, `stream`, and `time` fields and converts the log line from a JSON object into a plain log line for Loki.
